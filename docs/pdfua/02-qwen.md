# استشارة Qwen — قبل التنفيذ

**١. سلامة اللفّ مع q/Q وBT/ET:**
**حكم:** آمن بشروط. **سبب:** BMC/EMC ليسا من مُعاملات حالة الرسم، فيجوز أن يغلّفا q/Q بالكامل أو يوضعا داخلهما، لكن يُمنع قطع زوج q…Q أو BT…ET بـ EMC في المنتصف. القاعدة: BMC بعد q وقبل BT، وEMC بعد ET وقبل Q. إن وضعت BMC قبل q مباشرةً فهذا أسلم. الخطر الحقيقي في pikepdf: إن قطعتَ الـ content stream عند بايت خاطئ فستكسر الـ stream وتُنتج PDF تالفًا.

**٢. صورة الغلاف:**
**حكم:** Artifact. **سبب:** إن كانت زخرفية بحتة (شعار/غلاف بلا معلومات)، فـ Artifact مطابق لـ 7.3.1. إن حملت معنى (عنوان الكتاب مثلًا) وجب Figure + Alt + ActualText. الغلاف النموذجي = زخرفي = Artifact.

**٣. البنود التي ستنفجر بعد 7.1:**
**حكم:** ثلاثة على الأقل.
- **7.3 (اللغة الطبيعية):** إن وُجد نص لاتيني داخل /P بدون /Lang مُحدَّد.
- **7.18 (التعليقات التوضيحية):** الـ 43 Link تحتاج /Contents أو accessible name في الـ Annotation dict، وإلا فشلت.
- **7.2 (العناوين):** H1 التسعة إن لم تكن متداخلة هرميًّا صحيحًا (لا يجوز H1 ثم H1 بلا فاصل بنيوي واضح).

**٤. فخاخ إعادة بناء pikepdf:**
**حكم:** ثلاثة فخاخ قاتلة.
- **المرجع الدائري في StructTreeRoot:** pikepdf لا يتحقق من سلامة الشجرة؛ حذف عقدة دون تحديث /K أو /Pg يُنتج struct tree مكسورًا يمرّ بصريًّا ويفشل عند المدقّق.
- **ضغط الـ streams:** pikepdf قد يعيد ضغط content streams بفلتر مختلف عمّا تتوقعه عند حقن BMC/EMC — فكّ الضغط أولًا (`stream.read_bytes()`) ثم أعد الكتابة بـ `stream.write()` بدون فلتر أو بفلتر مطابق.
- **فقدان /StructParents:** عند إعادة بناء الصفحة، إن أنشأتَ page dict جديدًا دون نسخ /StructParents، تنفصل الصفحة
