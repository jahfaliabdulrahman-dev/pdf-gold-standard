# استشارة Qwen — إخراج بمواضع مطلقة

## الإجابات

**1) ما يجب حفظه صراحةً:**

عند استبدال كل `Td` بـ `Tm` مطلق، يجب نقل **كل حالة نصية نشطة** قبل أول `Tm` جديد:

- **Tf** (الخط + الحجم): إذا تغيّر بين محرفين، يجب إصدار `Tf` جديد قبل `Tm` الخاص بذلك المحرف.
- **Tz, Tc, Tw, Ts, Tr**: تُؤثّر في الموضع الفعلي. `Tc` و`Tw` تُضافان تلقائيًا بعد كل `Tj` في الوضع النسبي؛ عند التحويل لمطلق يجب **دمج أثرهما في إحداثيات Tm** أو إعادة إصدارهما.
- **TL**: لا أثر لها هنا لأنك لا تستخدم `T*` أو `'`.
- **q/Q**: إذا كان الكائن داخل `q…Q` يحوي تحويلًا (cm) خارجيًا، فالإحداثيات المطلقة يجب أن تُحسب **بعد** تطبيق ذلك التحويل، وإلا ستُنقل المحارف.

**2) خطر كسر التشكيل/الكشيدة أو تغيير ترتيب الاستخراج:**

- **بصريًا**: لا خطر على الكشيدة أو التشكيل، لأن الـ shaping تم مسبقًا (الـ GIDs ثابتة). لكن **عكس ترتيب المحارف في المحتوى** يجعل أي مستخرج نصي (pdftotext, PyMuPDF) يقرأها معكوسة، فيكسر البحث والنسخ.
- **حل**: أبقِ الترتيب الأصلي في stream ولا تعكس؛ أو أعد الترتيب المنطقي بعد الحساب.

**3) الفحص الآلي:**

```
render(A, 300dpi) → imgA
render(B, 300dpi) → imgB
assert pixel_diff(imgA, imgB) == 0
```
استخدم `pdf2image` + `PIL.ImageChops.difference` أو `compare -metric AE`. أي قيمة ≠ 0 تعني انزياحًا. بالإضافة: قارن `pdftotext` على الملفين؛ أي اختلاف في الترتيب يكشف المشكلة.

**4) أكبر خطأ متوقع:**

**تراكم الخطأ العشري (floating-point drift).** عند جمع سلسلة `Td` (كل قيمة قد تكون `0.001` مثلًا) ثم كتابتها كـ `Tm` مطلق، يظهر فرق ≈ 10⁻⁶ وحدة نصية. عند 300dpi وتكبير الخط، هذا يساوي **جزءًا من بكسل**، فيُغيّر anti-aliasing ويُنتج فرقًا بكسليًا. الحل: استخدام `Decimal` أو `Fraction` في الحساب، وتقريب الإحداثيات النهائية لأقرب 1/300 بوصة (≈ 0.00333 وحدة نقطية) لضمان ثبات الرندر.
