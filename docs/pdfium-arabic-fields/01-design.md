# تصميم رقعة PDFium: تشكيل العربية داخل حقول النموذج

> النسخة ٢ — بعد مراجعة طرف ثالث (Claude) حكمت `REQUEST CHANGES` بـ٤ عوائق؛ كل عائق أُغلق هنا أو حُوِّل إلى اختبار.
> الأساس المُثبت: PDFium عند `a8432342` لا يستدعي أي مُشكّل (`grep` = ٠)، وHarfBuzz هدف بناء `//third_party/harfbuzz` يبنيه Skia.

## ١. نموذج البيانات الحالي (المشكلة)

- `CPVT_VariableText` يخزّن `CPVT_Word` لكل **وحدة UTF-16**: `word` (uint16), `nFontIndex`, `ptWord`, `fWidth`.
- `CPWL_EditImpl::DrawEdit` (cpwl_edit_impl.cpp:594) يرسم كل كلمة عبر `DrawTextString` → `CPDF_TextRenderer::DrawTextString(..., word, ...)` (السطور 33–48).
- المؤشر والتحديد يعملان على فهارس الكلمات = فهارس المحارف. صحيح فقط عندما 1 محرف = 1 شكل — وهو ما لا يصحّ في العربية («لا» = شكل واحد).

## ٢. النموذج المقترح

### ٢.١ طبقة تخطيط بين النص والعرض

```
UTF-16 منطقي → ubidi (ICU) → مقاطع بصرية → HarfBuzz → محارف مرسومة
```

- `CPVT_Word` يحتفظ `word` المنطقي (للنسخ/البحث)، ويضيف `gid` (ما يُرسم)، `cluster` (فهرس المحرف الأول)، `fAdvance` (من HarfBuzz).
- `CPVT_Line` يحمل مقاطع مرتّبة بصريًا.
- **الرسم**: `SkTextBlob::MakeFromText(gids, …)` مرة لكل سلسلة، بدل نداء لكل محرف.

### ٢.٢ الاتجاه (bidi)

`ubidi_setPara` على نص الحقل، ثم `ubidi_countRuns/ubidi_getVisualRun`. النص المنطقي لا يتغيّر؛ الترتيب البصري يُخزَّن في `CPVT_Line`.
الأرقام واللاتينية تصير مقاطع LTR تلقائيًا (UBA).

### ٢.٣ المؤشر والتحديد — خوارزمية صريحة

**الحركة بالمؤشر**: خطوة `cluster` (لام-ألف خطوة واحدة).

**تحويل موضع بصري X إلى موضع منطقي** (السحب بالفأرة):
```text
for each visual run r in line (left→right on screen):
    if X inside r:
        d = distance from r's start edge to X          # في RTL يُقاس من اليمين
        offset_in_run = حرفٌ بعدد الحروف التي عرضها التراكمي ≈ d
        return r.logical_start + (rtl ? (r.length - offset_in_run) : offset_in_run)
```
- المصدر الرسمي للحدود: `ubidi_getVisualRun` + `ubidi_getLogicalRun` (ICU) — لا حساب يدوي للـUBA.
- **مستطيلات التحديد**: نمشي على المدى المنطقي (start,end)، ولكل محرف نجد مقطعه البصري، ونجمع مستطيلات كل مقطع منفصلة.

**النسخ**: يقرأ **المحارف المنطقية** من `CPVT_Word.word` (لا `gid`)، فيعود النص سليمًا إلى الحافظة. **اللصق**: محارف منطقية ثم إعادة تخطيط.

### ٢.٤ كتابة `/AP` — النقطة التي تنفع خارج Chrome

PDFium يبني المظهر في `CPDFSDK_Widget::ResetAppearance()` (`fpdfsdk/cpdfsdk_widget.cpp:669`)، ويُستدعى عند تغيّر القيمة (السطر 659) وعند الفتح (`cpdfsdk_pageview.cpp:111`).

المطلوب:
1. **التضمين عند الحفظ لا أثناء الكتابة**: نضمّن مجموعة فرعية من **المحارف المستخدمة فعلًا** (glyph ids) + `CIDSet`، كما يفعل `postprocess.form_font` في مشروعنا — لا خطًّا كاملًا لكل حقل.
2. **إعادة استخدام `/DR`**: إن كان الخط موجودًا في `AcroForm /DR` نُشير إليه ولا نضمّن نسخة ثانية (يفادي تضخّم الملف وتكرار الأوزان).
3. **`ToUnicode`**: يُبنى من `cluster → محرف منطقي` عبر `core/fpdfapi/font/cpdf_tounicodemap.{h,cpp}` (توليد قائم يُعاد استخدامه) — بدونه يفقد الملف البحث والوصول.
4. **حدّ القدرة (يُعلن، لا يُخفى)**: إن أعاد قارئٌ آخر توليد `/AP` عند التحرير، عاد نصّه هو. أي أن الفائدة عبر القرّاء **للقراءة والحفظ**، لا للتحرير الحيّ في Acrobat. هذا مُوثّق في §٥.

### ٢.٥ الاحتياط — بلا تناقض

- HarfBuzz **إلزامي للبناء** (هدف `//third_party/harfbuzz` موجود؛ لا `#if` يخفي الاعتماد).
- الاحتياط يعني: **خط بلا جداول GSUB** أو `hb_shape` بلا نتائج → المسار الحالي حرفًا حرفًا. لا يعني «بناء بلا HarfBuzz».

### ٢.٦ التراجع (Undo/Redo) — بالـcluster مع إعادة تخطيط

- مكدّس التراجع يخزّن **المدى المنطقي** (فهارس UTF-16) لا المحارف المرسومة.
- كل عملية (إدراج/حذف/استبدال) تُسجَّل بمداها المنطقي؛ وبعد التراجع **يُعاد التخطيط للسطر** فيُعاد تشكيل «لا» تلقائيًا.
- الحذف بـBackspace يحذف **cluster** كاملًا (حرفان لـ«لا»)، فيبقى التناسق بين ما يراه المستخدم وما يُسجَّل.

## ٤. اختبارات القبول (تُفشل اليوم، تنجح بعد الرقعة)

1. «لا» في حقل → عدد المحارف المرسومة = ١ (اليوم ٢).
2. «عبدالرحمن جحفلي» → حروف متصلة، اتجاه RTL.
3. مؤشر بعد «لا» ينتقل خطوة واحدة إلى ما بعدها.
4. Backspace على «لا» يحذف حرفين منطقيًا بضغطة.
5. «ملاحظة 2026» → الأرقام LTR داخل نص RTL.
6. سحب التحديد عبر «حظة 20» (يعبر حدود RTL/LTR) ثم **نسخ** → النص المنطقي صحيح عند اللصق.
7. `/AP` بعد الحفظ: MuPDF يعرض متصلًا، و`pdftotext` يعيد «ملاحظات» منطقيًا (لا معرّفات محارف).
8. خط بلا GSUB → المسار الحالي بلا تغيير (اختبار احتياط).
9. كتابة «ل» ثم «ا» (تتكوّن «لا») → Backspace يحذف الاثنين → **تراجع** يعيدهما وتُعاد «لا» مشكّلة.
10. حفظ من Chrome ثم فتح في Acrobat **بلا تحرير** ثم حفظ: يبقى `/AP` المشكّل (إن أعاد Acrobat التوليد عندها فقط نُعلن القيد في §٥).
11. حقول لاتينية: صفر فرق بصري وصفر فرق في `FPDF_GetFormFieldValue` (انحدار).
12. أداء: تشكيل سطر ٢٠٠ محرف ≤ ١ms (قياسنا: P95 = 0.017ms).

## ٥. ما لا تحلّه الرقعة

- التحرير الحيّ في Acrobat/Preview يبقى بمحرّك القارئ (خارج سيطرتنا).
- الفائدة عبر القرّاء تتحقق عند **القراءة والحفظ** لأن `/AP` يحمل الشكل الصحيح.
